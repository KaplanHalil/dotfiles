# Omarchy / Hyprland dotfiles

Syncs Omarchy + Hyprland configuration between two machines:

| host  | role    | GPU           | notes                             |
|-------|---------|---------------|-----------------------------------|
| `home`| this PC | AMD Radeon    | games, Steam/Lutris/Wine          |
| `tbtk`| work PC | NVIDIA + Intel| bitwarden, texlive, minecraft     |

Everything under `home/.config/` is shared and identical on both machines.
Packages are the exception: they are tiered so a package only ever reaches the
machine it belongs to (see [Packages](#packages)).

## What is synced

The repo mirrors `~/.config` exactly, so restoring is a plain tree copy:

- `hypr/` — keybindings, monitors, input, look & feel, autostart, night light
- `omarchy/shell.json` — bar layout and widgets
- `omarchy/extensions/` — launcher/menu extensions (`omarchy-menu.jsonc`)
- `omarchy/themes/<name>/` — custom theme overlays
- `omarchy/hooks/` — your `.hook` scripts (`*.sample` files are skipped)
- `omarchy/*.json`, `*.jsonc`, `*.toml` — e.g. `session-menu.jsonc`
- `alacritty/`, `kitty/`, `foot/`, `ghostty/`

Deliberately **not** synced, because they are per-machine or generated:

| Path | Why |
|------|-----|
| `omarchy/plugins/` | plain git clones; pinned in `plugins.txt` instead |
| `omarchy/shell.toml` | omarchy's machine-level override (`omarchy display text size`) |
| `omarchy/defaults/` | runtime state, e.g. the selected agent |
| `omarchy/branding/`, `themed/` | generated per install |

## Setup (new machine)

```sh
git clone git@github.com:KaplanHalil/dotfiles.git ~/.dotfiles
echo "<your host id>" > ~/.dotfiles-host-id     # home or tbtk
~/.dotfiles/restore-dotfiles.sh                # --force to skip prompts
~/.dotfiles/install-timer.sh                   # daily backup timer
```

Needs an SSH key at `~/.ssh/id_ed25519` (see <https://github.com/settings/ssh/new>).
The key must have **no passphrase**, otherwise the unattended timer push fails.

## Daily backup

```sh
~/.dotfiles/sync-dotfiles.sh      # copy configs, commit, push
~/.dotfiles/sync-github-repos.sh  # clone/pull your other GitHub repos
```

Automatic via a systemd user timer:

```sh
systemctl --user list-timers dotfiles-backup
journalctl --user -u dotfiles-backup -n 40
```

## Packages

`install-packages.sh` reads **only two tiers**: the shared tier and the tier for
`~/.dotfiles-host-id`. Another host's file is never opened, so a package on one
machine cannot reach the other even if a tier file is wrong.

| File | Who installs it |
|------|-----------------|
| `packages-shared.txt` (164) | every machine — curated by hand, **never** regenerated |
| `packages-shared-aur.txt` (1) | every machine — curated by hand |
| `packages-home.txt` (19) | `home` only — games, AMD drivers, build tools |
| `packages-home-aur.txt` (0) | `home` only |
| `packages-tbtk.txt` (20) | `tbtk` only — NVIDIA/Intel drivers, texlive, bitwarden |
| `packages-tbtk-aur.txt` (2) | `tbtk` only |

The per-host files hold the **delta** against the shared tier and are
regenerated by `sync-dotfiles.sh`. `shared + host` reproduces that machine
exactly.

Two safety properties worth preserving:

1. **The shared tier is hand-curated.** If `sync-dotfiles.sh` regenerated it from
   whichever machine ran the script, syncing from `home` would push its games
   into the shared tier and `tbtk` would install them.
2. **A denylist backstops the split.** `install-packages.sh` refuses games and
   GPU drivers found in the *shared* tier, even though a host's own tier is
   allowed to contain them.

```sh
~/.dotfiles/install-packages.sh --host home --dry-run
```

## Plugins

`plugins.txt` records each plugin's id, upstream URL and pinned commit, so both
machines end up on identical versions:

```
id                                  commit    repo
io.github.ehlxr.advanced-workspaces 76605c8  https://github.com/ehlxr/...
```

`restore-dotfiles.sh` clones and checks out the pinned commit. To update a
plugin on one machine, upgrade it there and re-run `sync-dotfiles.sh`.

## Troubleshooting

`SYNC-FIX-GUIDE.txt` covers conflicted repos and push failures.

```sh
# what the timer did last
journalctl --user -u dotfiles-backup -n 40

# what a sync would change, without committing
cd ~/.dotfiles && git status

# confirm configs match the repo
diff -r ~/.dotfiles/home/.config <what sync would produce>
```
